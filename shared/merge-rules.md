# 共用读取、证据与增量合并规则

> 七个 Skill 共用的读取范围、证据使用边界和增量合并规则，来自 `fde_toolkits_designSimplev0.6.md` 第 15.4 节和 `fde_toolkits_designSimplev0.7.md` 第 1.4、7.1、7.2、7.3 节。各 Skill 的 `SKILL.md` 引用本文件，不重复全文。

## 1. 读取范围

1. FDE 给具体文件时，只读取该文件及其中明确引用的必要文件。
2. FDE 给目录时，先按本轮目标、文件名、目录位置和更新时间筛选最相关材料，告知实际读取范围后直接处理，不要求逐文件批准；若候选仍过多或无法判断，先问岗位/场景范围，不默认遍历归档、发布物和全部历史版本。
3. 已有目标文件必须先读后改，保留与本轮证据无冲突的人工内容和结构。
4. 文件不可读时定位到具体文件并继续处理其他材料，不把文件名或目录名当作正文事实。
5. 若 FDE 只给目录，先列出本轮要用的文件再读取；不将目录里已有的最终答案（如既有 confirmed 成果）冒充原始访谈输入。若 FDE 只粘贴目录清单的文字描述、文件本体尚未提供，按描述形成假设并标注来源性质（"本轮 FDE 补充：目录描述"），文件正文内容一律列为待补，不把描述当作文件正文事实。
6. 扫描件或音频暂不可读时，指明文件并请提供文字/可读版本，同时继续处理其他资料。
7. 不默认遍历历史版本、客户原始证据和全部归档。
8. 资产化时客户项目只读，资产暂存目录为写入目标。
9. 复制源文件前先完成分类和权利/客户隔离判断。

## 2. 证据类型与使用边界

| 类型 | 可支持什么 | 不得怎样使用 |
|---|---|---|
| 客户确认或有效确认纪要 | 在确认覆盖范围内形成已确认事实 | 不扩展到纪要未覆盖的角色、场景、版本、文件、责任或系统域 |
| 任务观察、系统记录、真实样例 | 描述实际步骤、字段、结果和异常 | 一次样例不自动推成频率、SLA 或普遍规则 |
| 访谈原话 | 描述该角色的目标、做法、判断和问题 | 单一角色表述不自动解决跨角色责任冲突 |
| FDE 直接补充 | 作为本轮事实说明、范围选择或设计选择 | 未说明"客户已确认"时不得升级为客户确认 |
| 行业资料和 Skill 推演 | 生成假设、建议、培训草稿、可复用候选和待验证问题 | 不得写成客户现状、客户规则、客户授权或已确认需求 |
| 场景需求和蓝图（v0.7） | 场景目标、角色、流程、边界、内容组成 | 实际已经制作或已经交付的文件 |
| FDE 指定的源文件/目录（v0.7） | 实际存在的 Skill、代码、Prompt、模板和说明 | 文件未读取时不能根据文件名猜内容 |
| 客户项目经验（v0.7） | 形成资产候选和抽象问题 | 不能直接复制客户专属数据、配置或策略 |

设计文档和跨境电商示例只作为方法指导、模板和案例结构参考，不作为新客户项目的事实来源。每个主要结论至少标明文件路径/章节、原始材料、客户确认或"本轮 FDE 补充"；如果只是 Skill 根据现有内容提出的组织建议，必须标记为建议。

## 3. 增量合并与冲突规则

1. 同一输入重复执行应得到相同内容，不重复插入表格行、清单行、来源或问题。
2. 新证据只更新受影响章节；职责变化时检查场景定义、主流程、异常、验收和蓝图中的人工确认点。
3. 新内容与已有内容一致时补来源，不重写 FDE 已编辑的表达。
4. 新内容补充已有内容时合并细节，并保留原有来源。
5. 新内容与已有内容冲突时并列两种说法、来源（或路径、内容版本）和受影响章节，提出一个能解决冲突的具体问题；在确认前不静默覆盖。并列的落点：写入受影响章节本身（表格并列行或章节后引用块），并在来源/确认摘要中登记，不能只在一处记一句。
6. 较新的确认只覆盖其明确范围内的旧确认；不同范围或不同角色的说法不能仅按日期自动决定真伪。
7. 用户明确要求修改草稿时直接修改；若会改变已确认范围，必须在确认摘要中记录"原范围、变化、当前状态"。涉及已确认范围的冲突（并列保留、未覆盖）同样记录这三要素。
8. 已确认范围内的内容不得因新增访谈、观察或推演自动覆盖。只有 FDE 明确说明新的确认来源和覆盖范围，或明确要求将该部分退回草稿，才能修改其结论。
9. 同一字段冲突时按证据边界处理：新确认只在明确覆盖同一范围时替代旧内容；观察可修正推演但不能单独替代跨角色规则；不同角色访谈或两份有效确认互相冲突时并列保留并补问；FDE 的设计选择不能覆盖客户事实。
10. 每次更新后在目标文件的来源/确认摘要中写一条简短变更说明，包括"本轮输入、变更章节、仍未解决的冲突"；不额外创建变更表，除非项目已有该文件。FDE 转述的客户确认须标注"经 FDE 转述，原始纪要未提供"，并把原始纪要列入待补来源；声明存在确认纪要但本轮未读取原文的，同样按转述处理。

资产与移交场景（v0.7）追加规则：

11. 资产更新候选不得覆盖已有正式资产目录；同名 Skill/Prompt/代码版本冲突时，生成新候选版本或请资产 Owner 决定。
12. 共享资产变化后检查所有引用场景，但不自动修改场景结论。
13. 不执行删除、上传、公开发布或外部发送，除非用户另行明确要求且相关能力可用。

## 4. 场景文件的创建保护

Skill 可建议新增、拆分、合并或暂缓场景，并说明起终点和业务结果为何重叠或不同；只有 FDE 明确选择后才创建、合并、改 ID 或删除已有场景文件。不因发现候选场景就为所有候选建文件。

## 5. 项目脚手架的初始化保护

`fde-init` 初始化项目脚手架时不覆盖已有非空文件：目录骨架与空白文件已存在则跳过，重复执行幂等，不重复创建、不重复写入；FDE 新提供的信息只按增量合并规则更新项目总览受影响章节。目标目录已存在且含与本项目无关的内容时，提示风险并请 FDE 确认或更换目录，不静默覆盖。
