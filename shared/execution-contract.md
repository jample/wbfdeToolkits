# 共用执行契约：RunRequest、内部执行顺序与异常恢复

> 本文件是七个 Skill（`fde-init`、`fde-discovery-prepare`、`fde-discovery-capture`、`fde-design-blueprint`、`fde-deliver`、`fde-transfer`、`fde-assets-archive`）共用的执行约定，来自 `fde_toolkits_designSimplev0.6.md` 第 10、15 节和 `fde_toolkits_designSimplev0.7.md` 第 1.5、1.6、7.1、7.2 节。各 Skill 的 `SKILL.md` 引用本文件，不重复全文。

## 1. 内部 RunRequest（不要求 FDE 填表）

实现必须先从当前对话和文件位置自动归纳下面的内部 `RunRequest`。它不是外部 API 合同，不得要求 FDE 填 JSON、复制五行模板或逐字段回答。复杂任务时 FDE 可以自愿按五行表达（目标 / 项目位置 / 输入材料 / 直接补充 / 本次结果），与下表一一对应。

| 内部字段 | 是否必需 | FDE 可怎样提供 | 缺失时怎样处理 |
|---|---|---|---|
| `goal` | 是 | "准备销售访谈""整理询盘需求""完善询盘蓝图" | 根据对话判断；仍不明确时只问一次本轮目标 |
| `project_path` | 保存文件时是 | 项目目录或已有目标文件地址 | 可先在对话中给草稿；保存前再问目标位置 |
| `focus` | 否 | 岗位、场景、章节或本轮问题 | 从材料识别；只有多个候选会导致不同主要输出时才请 FDE 选择一次 |
| `source_paths` | 否 | 一个或多个文件/目录地址 | 允许只用 `direct_input` 开始；不因没有附件拒绝工作 |
| `direct_input` | 否 | 背景、原话、规则、例子、确认或设计选择 | 与文件输入同等处理，并标记为"本轮 FDE 补充" |
| `target_state` | 否 | "先出草稿""供客户确认""只补异常" | 默认生成可用草稿，不自动声明客户已确认 |

规则：

- `source_paths` 和 `direct_input` 至少有一个包含可用于当前目标的信息。只有项目位置而没有任何业务内容时，指出需要的最小业务信息，不扫描整个项目寻找可以拼成答案的既有正式成果。
- 对文件路径、来源 ID、章节和本轮直接补充做内部去重。同一路径或同一来源重复提供时复用已有分析，不要求 FDE 判断是否重复，也不重复写入来源和待补问题。
- 文件地址、直接回答、修改后的文档三种输入方式等价；已经读过且未变化的资料不要求再次提供。

交付、移交与资产化阶段（v0.7 新增）还应在内部推断以下字段，它们是内部执行信息，不是要求 FDE 学习的命令参数：

| 内部字段 | 含义 | 缺失时处理 |
|---|---|---|
| `scene_scope` | 本轮涉及的一个或多个 Scene ID | 从材料和 `focus` 识别；多个候选产生不同结果时请 FDE 选择一次 |
| `operation_intent` | 新建、盘点、补充、确认、归档或复用检查 | 从本轮目标判断 |
| `output_scope` | 客户项目、客户移交目录，或独立资产暂存目录 | 保存前必须明确；**资产输出目录必须与客户项目隔离**，资产化时客户项目只读，资产暂存目录才是写入目标；输出根目录指向客户项目时停止复制并要求独立暂存路径 |

## 2. 统一内部执行顺序

```text
识别目标与目标文件
→ 读取目标文件和最小相关来源
→ 判断新建还是增量更新
→ 按本 Skill 的步骤（I/A/B/C/D/E/F）生成或修订
→ 执行本 Skill 质量门
→ 最多提出 1–3 个高影响问题
→ 保存主要输出
→ 回复文件位置、状态、已完成范围、待补和下一步
```

- 不得把各步骤做成必须由用户点击确认的工作流节点。材料足够时应连续执行；只有涉及业务选择、事实冲突、人工责任或越权风险时才暂停补问。
- **项目根定位**：优先使用 FDE 明确给出的项目目录；未明确时，从目标文件向上查找含 `00_项目总览/项目总览.md` 的目录作为脚手架根；未找到脚手架时提示可用 `fde-init` 建立完整骨架，但不阻塞——仍按本 Skill 的阶段目录约定创建所需目录。
- 每个 Skill 可独立调用，不要求 FDE 先运行前一个 Skill。
- 统一对话循环（v0.7 §1.5）：先根据已有内容形成初稿再补问；每轮最多 1–3 个会改变范围、责任、交付内容或复用边界的问题；已能从材料回答的不重复问；FDE 回答"未知/以后补"后保留待补和影响，本轮不换说法追问；用户直接编辑 Markdown 与对话补充等价；同一输入重复运行不重复插入场景、文件、来源、问题或确认记录；已确认范围只有在 FDE 明确提供新的确认来源和覆盖范围时才能修改。

## 3. 异常恢复规则

| 情形 | 处理 |
|---|---|
| 目标文件不可读 | 不得覆盖原文件；报告原因并先在对话中给出草稿 |
| 部分来源不可读 | 定位到具体文件，继续使用可读材料，列出未覆盖范围；不把文件名或目录名当作正文事实，不猜测正文 |
| 生成中断 | 保留已完成内容为"草稿"，下次从质量门未通过项继续 |
| 质量门失败 | 先自动修复结构性缺项；仍缺业务事实时保存草稿并提出最多 1–3 个问题，不循环重写整份文档 |
| 单个过大文件或大量候选文件 | 缩小到相关章节或分块处理，明确已读/未读范围；不静默截断、不要求 FDE 手工拆表 |

## 4. 两层质量检查

- **结构检查**（可自动化）：确认目标章节、必要列、范围和来源状态存在。
- **语义检查**（由 Skill 执行）：确认未知项未写成事实、人工边界没有被 AI 动作覆盖、上下游输入输出一致。未通过项在最终回复中报告，不要求 FDE 逐条验表。

## 5. 可选的轻量状态文件

Skill 可在平台需要跨会话恢复时维护一个机器使用的轻量状态文件（如 `.fde/work-state.json`），只记录目标文件、已读来源、待补问题和最近更新时间。该文件由 Skill 自动维护，不是 FDE 交付物，不得要求 FDE 手工填写；若平台本身能可靠保存会话状态，则不需要创建。
