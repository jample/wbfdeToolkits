# fde-init：项目脚手架初始化

把"项目名称 + 项目概要"变成一套完整的 FDE 客户项目目录骨架：`00_项目总览/` 填入已提供的基本信息，`01`–`07` 各阶段目录只放两三行的用途说明占位，供其余六个内容 Skill 后续在对应阶段目录写入业务内容。本 Skill 只建骨架和占位，不代替任何内容 Skill 写业务文档。

## 1. 适用与不适用

**适用**

- 开始一个新的 FDE 客户项目，需要建立统一的 00–07 阶段目录骨架；
- 已有一段项目背景（项目名称、项目概要，可选客户简称/计划周期/项目 FDE/参与角色），希望落成项目总览；
- 目录中疑似已有脚手架，需要确认骨架完整性或补齐缺失的阶段目录与占位文件。

**不适用**

- 已有项目目录，要准备客户访谈 → `fde-discovery-prepare`；
- 要把访谈纪要整理成需求 → `fde-discovery-capture`；要设计智能体蓝图 → `fde-design-blueprint`；
- 要准备客户交付与培训 → `fde-deliver`；要整理客户移交 → `fde-transfer`；要提取可复用资产 → `fde-assets-archive`。

**最低可开始输入**：项目名称 + 一段项目概要。可选输入：客户简称、计划周期、项目 FDE、参与角色；缺则留待补。只有目标目录而没有任何项目信息时不代猜——按补问规则最多补问 1–3 个问题。

**主要输出**（写入 FDE 指定的项目根目录，即脚手架根）：

```text
<项目>/
├── 00_项目总览/
│   ├── 项目总览.md      # 填入项目名称+概要，其余章节留"待补"
│   └── 交付计划.md      # 空白模板（阶段/里程碑/负责人表格留空）
├── 01_预检/README.md            # fde-discovery-prepare 在此写 访前准备.md
├── 02_需求探究/README.md + scenes/   # fde-discovery-capture
├── 03_场景设计/README.md + scenes/   # fde-design-blueprint
├── 04_交付开发/README.md        # 占位：实施工作不由内容 Skill 生成，项目自行管理
├── 05_部署发布/README.md        # 同上
├── 06_交付与培训/README.md      # fde-deliver
└── 07_支持移交归档/README.md    # fde-transfer
```

各阶段 `README.md` 只有两三行：该目录用途、由哪个 Skill 写入什么文件。资产归档输出在客户项目之外，不进脚手架。模板见 [templates/项目总览.md](templates/项目总览.md)、[templates/交付计划.md](templates/交付计划.md)；填写样例见 [examples/项目总览.md](examples/项目总览.md)。**脚手架识别标志**：目录中存在 `00_项目总览/项目总览.md` 即视为已由本 Skill 初始化的项目根。

## 2. 内部 RunRequest

执行前先按 [../../shared/execution-contract.md](../../shared/execution-contract.md) 第 1 节从对话和文件位置自动归纳内部 `RunRequest`（goal / project_path / focus / source_paths / direct_input / target_state），不复制全文、不要求 FDE 填表。本 Skill 的两个落点：

- `goal` = 初始化项目脚手架；`focus` 为空（本 Skill 不涉及场景范围）。
- `project_path` 是保存骨架的必需信息；`direct_input` 至少包含项目名称和项目概要。只有目录没有任何信息时不代猜，按第 5 节补问。

统一内部执行顺序与异常恢复规则见 [../../shared/execution-contract.md](../../shared/execution-contract.md) 第 2–3 节。

## 3. 读取与保护规则

合并与冲突的完整规则见 [../../shared/merge-rules.md](../../shared/merge-rules.md)；本 Skill 要点：

1. 建立骨架前先检查目标目录：存在 `00_项目总览/项目总览.md` 即视为已初始化，转入幂等处理（见第 6 节），不重复创建。
2. 目标目录已存在且含与本项目无关的内容（如其他项目文件、无 FDE 项目结构的既有资料）时，提示风险并请 FDE 确认或换目录，**不静默覆盖**。
3. 已存在的非空文件一律**不覆盖**：FDE 或下游 Skill 已写入的内容保留原样，只补齐缺失的目录和空白文件。
4. 不读取目标目录以外的客户资料，不扫描其他项目寻找可复用的项目信息。

## 4. 执行步骤 I1–I3

方法定义与填写示例见 [references/methods.md](references/methods.md)。信息足够时应连续执行三步，不得把每步做成必须由用户点击确认的工作流节点；只有缺关键信息或存在覆盖风险时才暂停补问。

### I1｜收集项目基本信息

- **目的与方法**：用项目信息收集表把名称、概要（必填）与客户简称、计划周期、项目 FDE、参与角色（可选）分开，逐项标注来源（本轮 FDE 提供）或状态（待补）。
- **FDE 提供**：至少项目名称和一段项目概要；可选信息有则记录，没有不追问超过一轮。
- **Skill 加工**：逐项登记 → 必填缺失时按补问规则最多补问 1–3 个问题 → 可选缺失一律标"待补" → 不从项目名推测行业、规模、系统环境等客户事实。
- **补问示例**："项目名称和项目概要还没有——名称用于目录和总览标题，概要写入项目总览 §1；请先提供这两项，其余可留待补。"
- **写入章节**：项目总览 §1（项目基本信息）；未提供的可选项写入 §5 来源与待补。
- **完成判据与衔接**：名称与概要均已取得（或 FDE 明确"以后补"）即进入 I2。

### I2｜建立目录骨架与 00 两份文件

- **目的与方法**：按固定结构创建 00–07 目录；`00_项目总览/` 下按模板生成 `项目总览.md`（填入 I1 信息，其余章节标"待补"）和 `交付计划.md`（空白模板原样落盘）；其余阶段目录只创建对应 README 占位（内容见 [references/methods.md](references/methods.md) 第 2 节）。
- **FDE 提供**：目标目录（脚手架根）。
- **Skill 加工**：检查既有内容（第 3 节保护规则）→ 创建缺失目录 → 写 00 两份文件 → 写各阶段 README 占位 → 不创建骨架以外的目录和文件，不预先创建场景文件。
- **补问示例**：覆盖风险时："目标目录里已有与本项目无关的内容（如 xx 文件）。是直接在此初始化，还是换一个空目录？存在误覆盖风险，请确认。"
- **写入位置**：整个目录骨架。
- **完成判据与衔接**：骨架目录齐全、00 两份文件落盘、既有内容未被覆盖，进入 I3。

### I3｜汇报骨架位置、已填内容与待补项

- **目的与方法**：按补问规则的最终回复格式汇报，让 FDE 知道骨架在哪、填了什么、缺什么、下一步用哪个 Skill。
- **Skill 加工**：列出骨架根目录与已创建文件清单 → 说明项目总览已填入的字段 → 集中列出待补项（可选信息、项目背景与目标、交付计划各表）→ 给出下一步建议（如"提供业务背景后用 `fde-discovery-prepare` 开始访前准备"）。
- **完成判据**：最终回复包含文件位置、输出状态、已完成范围、待补和下一步（见第 8 节）。

## 5. 补问规则

完整排序和集合维护规则见 [../../shared/questioning-rules.md](../../shared/questioning-rules.md)；本 Skill 要点：信息足够时先建骨架再集中列待补，不逐字段盘问；每轮最多 1–3 个问题；FDE 回答"未知/以后补"后本轮不换说法追问，问题连同影响记入项目总览 §5。

本 Skill 特有的高影响问题（按优先级）：

1. **项目名称与概要**（必填缺失时）：影响项目总览 §1 和全部目录命名；不知道时不创建骨架，只在对话中说明需要的最小信息。
2. **覆盖风险**：目标目录已有无关内容时，确认"在此初始化"还是"换目录"；未确认前不写入。
3. **可选信息**（客户简称、计划周期、项目 FDE、参与角色）：只影响 §1 表格填写，通常作为待补项保存，不单独追问。

## 6. 目标文件创建与更新（幂等与保护）

- **不存在时**：按 I2 一次连续创建完整骨架；写不出内容的章节保留"待补"，不交空壳标题。
- **已初始化时**（存在 `00_项目总览/项目总览.md`）：**重复执行幂等**——骨架和空白文件已存在则跳过，不重复创建、不重复写入；FDE 新提供的信息只合并进项目总览对应章节，已在 §6 记录过本轮更新。
- **已有非空文件**：一律**不覆盖**——无论是本 Skill 此前生成的还是 FDE/下游 Skill 写入的内容；只补齐缺失项。
- **无关内容目录**：目标目录含与本项目无关的内容时提示风险并请 FDE 确认或换目录，不静默覆盖。
- 每次更新后在项目总览 §6 写一条简短变更说明（本轮输入、更新章节、尚未解决的冲突），不额外创建变更表。

## 7. 质量门

共用两层检查（结构/语义）见 [../../shared/quality-gates.md](../../shared/quality-gates.md) 和 [../../shared/execution-contract.md](../../shared/execution-contract.md) 第 4 节。本 Skill 的四条质量门：

1. 目录骨架齐全（00–07 阶段目录、00 两份文件、各阶段 README 占位）。
2. 项目总览含项目名称与项目概要。
3. 空白章节标"待补"而非虚构——未提供的信息不从项目名推测。
4. 未覆盖既有内容——已有非空文件原样保留。

四条全部通过标为"有条件可用"，可据此开始访前准备；可选信息（客户简称、周期、角色）未补齐不构成阻塞。门未全部通过时保持"草稿"，先自动修复结构性缺项（如补齐缺失目录），仍缺必填信息时提出最多 1–3 个问题。

## 8. 最终回复格式

按 [../../shared/questioning-rules.md](../../shared/questioning-rules.md) 的每步回应格式组织，必须包含：

1. **文件位置**：脚手架根目录和已创建文件的清单；未写入时明确说明。
2. **输出状态**：草稿 / 有条件可用（附质量门未通过项）。
3. **已完成范围**：建立了哪些目录、项目总览填入了哪些字段。
4. **待补材料**：具体缺口、会影响什么、如何继续。
5. **下一步**：建议动作（如"提供业务背景后用 `fde-discovery-prepare` 开始访前准备"）。

## 9. AI 约束

- 不虚构客户事实：未提供的信息一律标"待补"，不从项目名推测行业、规模、系统环境或联系人的字。
- 不覆盖已有非空文件；重复执行幂等，不重复创建骨架或重复写入。
- 目标目录含与本项目无关的内容时提示风险并请 FDE 确认，不静默覆盖。
- 只创建本 Skill 定义的骨架结构，不代替下游 Skill 预建业务文件（如访前准备、场景需求），不创建空场景目录凑结构。
- 项目总览和交付计划是项目级管理文档，不含客户业务结论；业务内容一律由对应阶段 Skill 后续写入。
