# fde-init 方法说明

本文件定义项目初始化 Skill 使用的三个方法，对应 `SKILL.md` 的执行步骤 I1–I3。每个方法给出定义、要填字段、使用步骤和一个填写示例，以及结果落盘位置。本 Skill 为本项目新增，无上游设计文档章节；风格与 v0.6 各 Skill 的方法说明对齐。

## 1. 项目信息收集表

**定义**：把 FDE 提供的项目基本信息按"必填 / 可选"分开登记的一张表。识别的是"骨架里能填什么、什么要留待补"，不是项目业务结论。

**要填字段**：项目名称（必填）/ 项目概要（必填）/ 客户简称（可选）/ 计划周期（可选）/ 项目 FDE（可选）/ 参与角色（可选），每项附来源或状态。

**使用步骤**：

1. 逐项登记 FDE 提供的信息，来源标"本轮 FDE 提供"；
2. 必填项缺失时按补问规则最多补问 1–3 个问题；FDE 明确"以后补"则记录待补并继续可继续的部分（缺必填项时不创建骨架）；
3. 可选项缺失一律标"待补"，不追问超过一轮；
4. 不从项目名推测行业、规模、系统环境等客户事实——概要里没写的就是未知。

**填写示例**（写入项目总览 §1）：

| 字段 | 填写结果 | 来源/状态 |
|---|---|---|
| 项目名称 | 蓝湾跨境销售智能体项目 | 本轮 FDE 提供 |
| 项目概要 | 为蓝湾跨境的销售团队构建 WorkBuddy 智能体，首期聚焦询盘处理与销售跟进两个方向 | 本轮 FDE 提供 |
| 客户简称 | 蓝湾跨境 | 本轮 FDE 提供 |
| 计划周期 | 待补 | 未提供 |
| 项目 FDE | 待补 | 未提供 |
| 参与角色 | 待补 | 未提供 |

**汇入章节**：项目总览 §1 项目基本信息；未提供项同时列入 §5 来源与待补。

## 2. 项目骨架生成

**定义**：按固定结构创建 00–07 阶段目录，`00_项目总览/` 落两份文件，其余阶段目录只放两三行的 README 占位。

**固定结构**：

```text
<项目>/
├── 00_项目总览/
│   ├── 项目总览.md      # 按 templates/项目总览.md 生成，填入 I1 信息，其余章节标"待补"
│   └── 交付计划.md      # 按 templates/交付计划.md 原样落盘（空白模板）
├── 01_预检/README.md
├── 02_需求探究/README.md + scenes/
├── 03_场景设计/README.md + scenes/
├── 04_交付开发/README.md
├── 05_部署发布/README.md
├── 06_交付与培训/README.md
└── 07_支持移交归档/README.md
```

**各阶段 README 占位内容**（原样写入，不改写）：

- `01_预检/README.md`：本目录存放访前准备产物。由 `fde-discovery-prepare` 在此写入 `访前准备.md`；访谈取得纪要后交给 `fde-discovery-capture`。
- `02_需求探究/README.md`：本目录存放需求探究产物。由 `fde-discovery-capture` 写入 `角色与场景总览.md` 和 `scenes/<scene-id>/scene-requirement.md`。
- `03_场景设计/README.md`：本目录存放智能体蓝图。由 `fde-design-blueprint` 写入 `scenes/<scene-id>/scene-blueprint.md`。
- `04_交付开发/README.md`：本目录为实施与开发工作区。Skill、Prompt、代码等实际制作由项目自行管理，不由内容 Skill 生成。
- `05_部署发布/README.md`：本目录为部署与发布工作区，由项目自行管理，不由内容 Skill 生成。
- `06_交付与培训/README.md`：本目录存放客户交付与培训内容。由 `fde-deliver` 写入 `交付内容总览.md`、`培训与使用指南.md` 和 `scenes/<scene-id>/场景交付说明.md`。
- `07_支持移交归档/README.md`：本目录存放客户移交与支持内容。由 `fde-transfer` 写入 `客户移交总览.md`、`内容维护与支持说明.md` 和 `scenes/<scene-id>/场景移交说明.md`。

**使用步骤**：

1. 按第 3 节方法检查目标目录（幂等与覆盖保护）；
2. 创建缺失的阶段目录与 `scenes/` 子目录；
3. 生成 00 两份文件：项目总览填入 I1 信息、交付计划为空白模板；
4. 写入各阶段 README 占位；
5. 不创建骨架以外的目录和文件，不预建场景文件和业务文档。

**汇入位置**：整个目录骨架；项目总览 §3 阶段目录说明同时记录同一对应关系。

## 3. 幂等与覆盖保护

**定义**：保证 fde-init 可安全重复执行、永不破坏既有内容的一组判断规则。

**判断顺序**：

1. **识别标志**：目标目录中存在 `00_项目总览/项目总览.md` → 视为已初始化的脚手架，转入幂等处理；
2. **无关内容**：不存在识别标志，但目录含与本项目无关的内容（其他项目文件、无 FDE 项目结构的既有资料）→ 提示风险并请 FDE 确认或换目录，未确认前不写入，不静默覆盖；
3. **幂等处理**：骨架和空白文件已存在则跳过，不重复创建、不重复写入；FDE 新提供的信息（如补上的计划周期）按增量合并规则只更新项目总览受影响章节，并在 §6 记录本轮更新；
4. **非空保护**：已存在的非空文件一律不覆盖——无论是本 Skill 此前生成的、FDE 手工编辑的，还是下游 Skill 已写入的（如 `01_预检/访前准备.md`）。

**重复执行示例**：第一次执行建立完整骨架后，FDE 再次说"初始化这个项目"——Skill 识别 `00_项目总览/项目总览.md` 已存在，逐项核对骨架完整性，发现齐全则回复"骨架已存在，未做任何改动"；若 FDE 同时补充了"计划周期 2026-10 至 2026-12"，则只更新项目总览 §1 对应行和 §6 本轮更新，其余不动。

**汇入位置**：判断结论写入最终回复；增量更新写入项目总览 §6 本轮更新。
