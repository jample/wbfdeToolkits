# fde-assets-archive：WorkBuddy 场景资产归档 Skill

从完整客户项目中识别可复用内容，按"共享核心 + 每场景资产"的结构进行来源追溯、客户隔离、参数化和文件组织，形成包含 WorkBuddy Skills、专家、提示词、提示词模板、源代码、MCP 配置说明、交付模板和合成示例的**待评审资产包**，供后续项目选择、适配和复用。

## 1. 为什么独立成 Skill

客户移交（`fde-transfer`）和资产归档解决两个不同问题：移交保留客户专属内容和权利边界，归档必须隔离或参数化客户身份、数据、配置、凭证和内部策略。如果资产生成放在移交中，容易把客户专属内容错误带入通用资产，或把内部核心错误放入客户包。因此 `fde-transfer` 只生成资产化输入提示；文件抽取、通用化和资产包生成由本 Skill 单独执行，且**两条信息流不使用同一个目录**。

## 2. 资产颗粒度：场景最小，项目负责聚合

默认每个场景形成一个可独立复用的资产单元。项目级资产包只做三件事：列出本项目包含的场景资产；保存被多个场景明确共用的 WorkBuddy 内容（放 `shared/`，场景清单引用同一版本）；说明场景之间的依赖和推荐组合。客户特定的术语、输出格式和字段不进入通用核心，只转成可填写的客户覆盖模板或直接排除。

## 3. 适用与不适用

适用：

- 项目已有需求、蓝图、实际 WorkBuddy 内容和交付说明，需要形成内部资产候选；
- 将一个项目的多个场景拆成可独立复用的场景资产；
- 归档 WorkBuddy Skills、专家、Prompt、模板、源代码和 MCP 配置说明；
- 把客户术语、目录、字段和输出格式转成参数化覆盖模板；
- 形成资产清单、来源追溯、脱敏检查、复用边界和二次交付指南；
- 更新已有资产包，并说明本项目带来的增量（生成更新候选，不覆盖正式资产）。

不适用：

- 只需准备当前客户交付内容 → `fde-deliver`；只需完成当前客户移交 → `fde-transfer`；
- 需要初始化新项目脚手架（建立 00–07 目录骨架）→ `fde-init`；
- 没有权利或无法隔离客户敏感内容 → 只能生成候选分析，不复制受限文件；
- 要直接上架、公开、发送给其他客户或覆盖正式资产 → 本 Skill 只能形成待评审包；
- 要执行源代码、MCP 或外部工具 → 本 Skill 只组织文件和说明。

## 4. 最低输入和关键确认

| 输入 | 是否最低需要 | 缺失时处理 |
|---|---|---|
| 客户项目路径 | 是 | 作为来源读取，不在原项目中改写通用版本 |
| 资产暂存输出根目录 | 生成文件包时是 | 未提供时先生成资产候选分析，不复制文件 |
| 场景范围 | 是 | 一个或多个 Scene ID；多个候选时请 FDE 选择一次 |
| 场景需求和蓝图 | 是 | 用于抽象业务问题、边界和可适配点 |
| 实际 WorkBuddy 内容路径 | 是 | 至少有一种真实内容；文件未读取时不根据名称猜内容；若阶段 4/5 尚未开展、内容尚不存在，如实登记缺失，只对需求/蓝图做抽象候选，不虚构路径 |
| 客户交付/移交内容 | 否但建议 | 帮助识别实际使用方式和客户适配 |
| 复用权利与限制 | 生成可复用包时是 | 不清楚时复用状态保持"禁止复用"或"待脱敏与评审"（三值定义见 [references/de-identification-rules.md](references/de-identification-rules.md) §3） |
| 客户敏感和排除规则 | 是 | 客户名称、数据、字段、端点、凭证、策略、第三方内容等 |
| 已有资产库检索结果 | 否 | 用于判断新增、更新、合并或不重复建设 |

正式复制文件前，至少确认五件事：资产化范围（单场景/多场景/项目集合）；输出根目录不位于客户项目或客户交付包内部；哪些文件有权进入内部资产候选、哪些必须排除；客户专属内容是参数化、合成重制还是完全排除；已有正式资产是否存在、当前是新建还是更新候选。

## 5. 内部 RunRequest

先从对话和文件位置自动归纳内部 `RunRequest`（goal / project_path / focus / source_paths / direct_input / target_state，以及 scene_scope / operation_intent / output_scope），规则见 [../../shared/execution-contract.md](../../shared/execution-contract.md)。不得要求 FDE 填 JSON 或固定表单。

本 Skill 特别强调 `output_scope`：本 Skill 的输出目标是**独立资产暂存目录**，不默认写入客户项目；输出根目录指向客户项目或客户交付包内部时，**停止复制并要求独立暂存路径**，此前只生成候选分析。

## 6. 读取与写入规则

通用读取范围、证据边界与增量合并规则见 [../../shared/merge-rules.md](../../shared/merge-rules.md)。本 Skill 特别强调其中两条：

- **资产化时客户项目只读，资产暂存目录为写入目标**：不修改客户项目原文件来形成通用版本；
- **客户项目根定位**：优先使用 FDE 明确给出的项目目录；未明确时，从来源文件向上查找含 `00_项目总览/项目总览.md` 的目录作为脚手架根；未找到脚手架时提示可用 `fde-init` 建立完整骨架，但不阻塞本 Skill——仍按 FDE 给出的项目路径只读处理（每个 Skill 可独立调用）；
- **复制源文件前先完成分类和权利/客户隔离判断**：未通过分类和权利判断的文件只登记，不复制。

其余写入规则：不覆盖已有正式资产目录；同名 Skill/Prompt/代码版本冲突时生成新候选版本或请资产 Owner 决定；共享资产变化后检查所有引用场景但不自动修改场景结论；不创建空目录凑结构；不默认压缩为 ZIP、不自动上传或发布。

## 7. 执行步骤 F1–F7

七步是 Skill 内部方法，不是用户子命令。材料齐时连续执行，只在实质缺口处补问。**实施顺序上先支持"候选分析"（F1–F3，无输出目录也可完成），再支持独立目录资产包生成（F4–F7），降低客户资料误复制风险。** 各步详细方法见 [references/archive-methods.md](references/archive-methods.md)。

### F1｜确定资产化范围和输出位置

- **目的**：确认本轮按哪个场景或场景组合资产化、输出到哪里、与已有资产什么关系。
- **FDE 可提供**：客户项目路径、本轮 Scene ID、独立资产暂存根目录、已有资产库检索结果。
- **Skill 加工**：识别项目、场景、已有资产、输出根目录和本轮目标；默认逐场景资产化，只有 FDE 明确要求时才生成多场景项目集合；检查输出根目录是否独立于客户项目。
- **产出/写入位置**：候选分析结论留在对话；无论输出目录是否已提供均继续进入 F2、F3（仅分析模式），只有从 F4 起的文件生成才需要合法输出目录。
- **确认点**：场景或场景组合；输出根目录位置。输出目录未提供或位于客户项目内部时，只生成候选分析，不复制文件。
- **完成判据**：范围、输出位置（或"仅候选分析"模式）和新建/更新关系明确。

### F2｜盘点项目并建立来源映射

- **目的**：建立"项目文件 → 场景 → 内容类型 → 计划处理方式"映射。
- **FDE 可提供**：场景需求、蓝图、阶段 4/5 文档和实际资产路径。
- **Skill 加工**：只读取与本轮场景相关的材料，不默认把全部项目档案纳入；逐项登记来源路径和内容类型。
- **产出/写入位置**：初版 `资产包清单.md` 和 `来源与转换追溯.md`（生成文件包模式）或对话中的候选清单（仅分析模式）。
- **确认点**：哪些实际 WorkBuddy 文件是候选，哪些只是项目证据。
- **完成判据**：所有候选文件有真实路径和场景归属；未读取的不写成已存在。

### F3｜分类可复用核心、客户覆盖和排除项

- **目的**：按内容分类模型（可复用核心/参数化模板/场景专属/跨场景共享/客户覆盖/项目证据/受限内容，详见 [references/archive-methods.md](references/archive-methods.md)）对每个候选文件分类。
- **FDE 可提供**：复用权利说明、客户敏感和排除规则、客户差异处理方式的选择。
- **Skill 加工**：逐文件执行分类；特别检查客户专属 Prompt 能否安全参数化、字段映射是否转成空白覆盖模板、源代码是否含客户常量或第三方内容、MCP 配置是否含客户地址/账号/凭证/Schema、项目证据是否被误当资产示例；冲突或权利不清时不复制，先补问。
- **产出/写入位置**：各文件的处理方式（原样复制/参数化/合成重制/仅引用/排除）写入清单与追溯。
- **确认点**：复用权利；客户差异参数化、合成重制还是排除。
- **完成判据**：每个候选有明确分类和处理方式；权利不清项标"待确认/禁止复用"，未默认放行。

### F4｜生成场景资产骨架和共享结构

- **目的**：按资产包目录结构（详见 [references/archive-methods.md](references/archive-methods.md)）创建实际需要的目录，不创建空目录。
- **FDE 可提供**：共享资产归属的确认（哪些内容真正跨场景共享）。
- **Skill 加工**：为每个场景生成 `资产清单.md`、`场景定义.md`、`场景蓝图.md` 和复用指南骨架；被两个及以上场景明确共用的内容放入 `shared/`，场景文件通过相对路径引用；场景定义和蓝图从客户版本抽象为通用版本，保留任务、流程和边界，移除客户专属结论，无法通用化的部分放入客户覆盖模板或排除。
- **产出/写入位置**：`<资产暂存根目录>/<asset-package-id>/` 下的场景目录和 `shared/`。
- **确认点**：哪些内容是真正跨场景共享。
- **完成判据**：目录与实际内容一一对应；场景定义可独立理解；无空目录。

### F5｜归档 WorkBuddy 内容和原生文件

- **目的**：在权利和客户隔离允许的范围内，把实际 Skill、专家、Prompt、模板、代码和 MCP 说明复制/重制到对应目录。各类资产的归档要求和检查项见 [references/workbuddy-asset-types.md](references/workbuddy-asset-types.md)。
- **FDE 可提供**：各资产的内容版本、Owner、复用权利状态；同名正式资产冲突时的选择。
- **Skill 加工**：复制/重制文件；为原生文件生成 Markdown 索引和说明；不修改客户项目原文件、不覆盖已有正式资产、同名冲突生成更新候选或请 FDE 选择；无法读取或无法确认权利的文件只登记不复制；复制后执行内容级客户隔离检查（脱敏规则见 [references/de-identification-rules.md](references/de-identification-rules.md)），不能只检查文件名。
- **产出/写入位置**：`workbuddy/`、`source-code/`、`integration/` 各子目录及索引说明。
- **确认点**：同名/版本冲突处理；权利待确认项是否本轮排除。
- **完成判据**：每个复制文件完成内容级隔离检查；排除项在治理文档中有原因记录。

### F6｜生成二次交付和客户覆盖指南

- **目的**：为未来 FDE 说明怎样选择场景和共享资产、复制或引用哪些内容、怎样填写客户覆盖、哪些内容需要重新开展客户需求确认、怎样利用 `fde-deliver` 生成新客户交付材料、哪些变化属于资产核心调整必须提交专业 FDE/资产 Owner。
- **FDE 可提供**：复用时的典型适配顺序和注意事项（如有）。
- **Skill 加工**：将参数化点整理为变量、填写说明和合成示例；客户覆盖模板只含变量、说明和合成示例，不含真实客户值。
- **产出/写入位置**：每场景 `enablement/场景复用指南.md`、`客户覆盖模板.md` 和可选培训材料模板。
- **确认点**：无（结构性内容）；客户覆盖变量完整性存疑时列为待补。
- **完成判据**：后续 FDE 不看原项目也能完成场景选择、客户覆盖填写和适配边界判断。

### F7｜完成隔离、复用和评审准备

- **目的**：检查文件路径、场景映射、共享引用、来源追溯、客户信息、权利和复用说明，形成最终状态判断。
- **FDE 可提供**：专业评审/资产 Owner 的确认结果（如有）。
- **Skill 加工**：执行资产包门（见第 10 节）；填写治理文档（[references/de-identification-rules.md](references/de-identification-rules.md)）；按"草稿候选 / 待评审资产包 / 已确认范围资产包 / 禁止复用"定级——Skill 不自我批准，"已确认范围"必须有明确专业评审或 Owner 确认来源。
- **产出/写入位置**：`governance/` 四份治理文档、`资产包总览.md` §7 状态与限制。
- **确认点**：最终是草稿、待评审，还是已有明确确认范围。
- **完成判据**：资产包门七条逐项有结论；状态不高于实际证据支持的级别。

## 8. 交互确认点汇总

只在以下信息会改变资产结果时补问：本轮按哪个场景或场景组合资产化；独立资产输出目录在哪里；哪些实际 WorkBuddy 文件是候选、哪些只是项目证据；哪些内容有复用权、哪些权利未知；客户差异应参数化、合成重制还是排除；哪些内容是真正跨场景共享；与已有资产的关系是新建、更新、合并还是不重复建设；最终只是草稿、待评审，还是已有明确确认范围。

## 9. 补问规则

通用规则见 [../../shared/questioning-rules.md](../../shared/questioning-rules.md)：每轮先出可见初稿（候选分析或骨架），再按影响排序最多提 1–3 个问题，已能回答的不重复问，FDE 答"未知/以后补"后本轮不换说法追问。本 Skill 特有的高影响问题：

- **复用权利**：该内容是否允许跨客户复用？权利不清时标待确认，不默认放行；
- **客户隔离**：输出根目录是否独立于客户项目？（指向客户项目时停止复制并要求独立暂存路径）
- **共享资产归属**：该 Skill/Prompt/专家是否被两个及以上场景明确引用？（"可能以后共用"不是共享事实）
- **已有正式资产版本冲突**：同名正式资产已存在时，生成新版本更新候选还是请资产 Owner 决定？不静默替换。

## 10. 质量门

三类状态（文档/交付/复用）定义见 [../../shared/quality-gates.md](../../shared/quality-gates.md)，不能互相推断。本 Skill 资产包门（七条）：

1. 每个场景形成独立业务闭环，项目共享资产有明确引用；
2. WorkBuddy Skill、专家、Prompt、模板、代码和 MCP 说明有完整清单；
3. 每个资产包文件能回到项目来源和转换动作；
4. 客户覆盖、项目证据和受限内容已隔离；
5. 权利和第三方依赖有状态；
6. 有复用指南、客户覆盖模板和合成示例；
7. 未经专业确认不写成正式可发布资产。

## 11. 最终回复格式

遵循 [../../shared/questioning-rules.md](../../shared/questioning-rules.md) 的 v0.7 七项约定，每轮结束必须说明：创建或更新了哪些文件；本轮覆盖哪些项目、场景和内容；文档状态、交付状态或复用状态（本 Skill 主要报告复用状态：禁止复用/待脱敏与评审/可在确认范围内复用）；已读取的关键来源和未读取/不可读内容；已完成什么、仍缺什么、缺口会影响什么；哪些是 FDE 建议、哪些是客户或资产 Owner 已确认；下一步使用哪个 Skill、补什么材料或进入谁的评审。

## 12. AI 约束

- 不把客户特定术语和字段写成通用资产默认值；
- 权利不清时不默认客户获得源代码，也不默认悦智能跨客户复用；
- 不只删除客户名称就宣称已经脱敏；
- 不把客户配置、域名、Token、账号、日志或真实 Schema 写入资产包；
- 不把资产候选写成已评审、已入库或已公开；
- 不修改客户项目原文件来形成通用版本；
- 不覆盖同名正式资产或静默改变资产版本；
- 不根据蓝图虚构不存在的 Skill、源代码、Prompt、MCP 说明或文件路径；文件未读取时不根据文件名猜正文；
- 不把内部 Prompt 试验、原始访谈或客户样例当作可复用资产复制进资产包；
