# 客户隔离与脱敏规则、治理文档填写方法

> 本文件规定资产化过程中怎样隔离客户身份与敏感内容、怎样判断"脱敏是否成立"，以及 `governance/` 四份治理文档的填写方法。

## 1. 脱敏判定标准

**只删除客户名称不算脱敏。** 一份内容只有通过以下全部检查，才能标为"已参数化"或"已用合成内容重制"：

1. 客户名称、品牌、组织、人员姓名已全部移除或参数化；
2. 账号、租户、域名、内网地址、端点 URL 不含真实值；
3. 凭证、Token、密钥只保留引用方式说明，无任何明文值；
4. 客户数据、真实样例、日志、截图、录音不进入资产包；
5. 客户业务策略、价格、合同条款不进入通用核心；
6. 真实字段名/Schema 已改为业务语义变量；
7. 文件批注、修订记录和元数据中的客户信息已清理；
8. 合成示例使用虚构公司、虚构人员和虚构数据，且不能由真实值改几个字得到；
9. 资产包 ID、目录名和资产命名本身不含客户名称或客户可识别标识。

检查必须在**内容级**执行（逐文件读正文），不能只检查文件名和目录名——但第 9 项反过来要求命名本身也要脱敏。治理文档（追溯、隔离检查、权利、评审记录）自身同样要过以上检查：登记排除原因时只说明内容类别和排除理由，不抄录被排除的具体值。

## 2. 各资产类型的参数化/合成重制要求

| 资产类型 | 参数化对象 | 合成重制对象 | 必须排除 |
|---|---|---|---|
| WorkBuddy Skill | 角色称谓、目录路径、输出模板引用 | 示例任务和示例输入 | 客户专属流程分支、客户系统操作步骤 |
| 专家与专家团 | 角色称谓、服务对象描述 | 示例问答 | 客户组织名称、具体人员、客户专属职责 |
| Prompt 与 Prompt 模板 | 客户名称、目录、输出格式、风格变量 | 一条完整合成输入/输出示例 | 客户策略、人员、价格、账号、专属字段 |
| 源代码 | 配置项、路径、常量改为变量或配置引用 | 示例配置、示例数据 | 客户常量、内网地址、凭证、权利不明的第三方代码 |
| MCP 配置说明和模板 | 服务地址、租户、字段名改为占位变量 | 完整合成配置片段和合成数据样例 | 真实域名、Token、账号、真实 Schema、真实日志 |

参数化的通用做法：变量命名使用 `${business_semantic_name}` 形式表达业务语义（如 `${sales_role_name}`、`${brief_section_titles}`），不使用 `${customer_xxx}` 这类暴露来源的命名；每个变量在覆盖模板中给出含义、必填/可选、合成示例值和缺失处理。

## 3. 复用状态字段

资产包内所有清单和治理文档的复用状态统一使用三个值：

| 复用状态 | 含义 |
|---|---|
| 禁止复用 | 存在无法隔离的客户内容、权利限制或严重缺失，不进入资产包 |
| 待脱敏与评审 | 结构完整但脱敏或权利尚待专业确认 |
| 可在确认范围内复用 | 有明确专业评审/资产 Owner 确认及适用范围 |

该状态不能由 Skill 自行升级到"可在确认范围内复用"；必须有明确确认来源。

## 4. 治理文档填写方法

四份治理文档位于 `<asset-package-id>/governance/`，空白模板在 [../assets/templates/](../assets/templates/)。

### 4.1 `来源与转换追溯.md`

逐文件记录资产包内容从哪来、经过了什么转换：

| 字段 | 填写要求 |
|---|---|
| 资产包文件 | 新资产包中的相对路径 |
| 来源项目文件 | 原项目受控路径（不暴露到对外资产说明） |
| 来源类型 | 需求 / 蓝图 / Skill / Prompt / 代码 / 配置说明 / 交付材料 |
| 转换动作 | 原样复制 / 抽象 / 参数化 / 合成重制 / 合并 / 排除 |
| 转换说明 | 删除或替换了什么，为什么仍保留业务含义 |
| 责任人/日期 | 谁进行或确认了转换；无事实时标待补 |
| 复用限制 | 是否待权利确认、是否禁止外部使用 |

被排除的文件也要登记一行（转换动作 = 排除，写明原因），否则无法区分"已排除"和"漏处理"。

### 4.2 `客户隔离检查.md`

至少逐项检查：客户名称与品牌、人员与组织、账号/租户/域名、内网地址、凭证、客户数据、业务策略、价格合同、真实字段/Schema、日志截图、录音、批注和文件元数据。

每项结论使用五种之一：**未发现 / 已参数化 / 已用合成内容重制 / 排除 / 待人工确认**，并写明处理位置（哪个文件、哪个变量）。存在"待人工确认"项时，资产包整体状态不得高于"待脱敏与评审"。

### 4.3 `权利与复用边界.md`

分四类登记：内部自研、客户提供、第三方依赖、权利未知。每类说明允许范围：允许内部参考 / 允许项目复用 / 允许对外交付 / 禁止复用。

Skill 不进行法律判断：只有明确来源/授权才能记录相应范围；权利未知一律标"待确认"，不默认放行。第三方依赖须登记许可状态，不得隐去许可问题。

### 4.4 `资产包评审记录.md`

按八个维度记录评审准备情况和结论：业务完整性、场景颗粒度、WorkBuddy 内容完整性、客户隔离、权利、依赖、复用说明、待补项。

形成待评审包后由专业 FDE/资产 Owner 做实际判断，**Skill 不自我批准**：Skill 只能填"自查结果"列和待补项；"评审结论"列只有 FDE 提供明确评审/确认来源后才能填写，并记录确认人和范围。

## 5. 常见误判

- **误判**：把客户名称替换成"某客户"就标为已脱敏。**正解**：域名、字段、策略、样例数据、元数据仍在，仍需逐项过第 1 节检查。
- **误判**：客户实际输出改几个数字后当作合成示例。**正解**：合成示例必须从虚构业务情况重新构造，不能由真实值改写。
- **误判**：权利未知的代码"先复制进包，评审时再定"。**正解**：权利未知不复制，只在追溯文档登记。
- **误判**：项目证据（访谈纪要、截图）作为"真实示例"放入 examples/。**正解**：项目证据只在追溯中受控引用，examples/ 只放合成示例。
