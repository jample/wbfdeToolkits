# fde-assets-archive 方法与目录规则

> 本文件承载 `fde-assets-archive` 的详细方法：内容分类模型、资产包目录结构、总览与清单内容合同、F1–F7 各步详细做法和完整示例。`SKILL.md` 只保留触发边界和执行骨架。

## 1. 内容分类模型

对每个候选文件先分类，再决定处理方式。分类不确定或权利不清时，不复制，先补问。

| 分类 | 定义 | 资产包处理 |
|---|---|---|
| 可复用核心 | 与客户身份无关、解决通用任务的 Skill、Prompt、专家、代码或方法 | 保留原结构，补充来源和版本说明 |
| 参数化模板 | 结构通用，但客户术语、目录、字段、格式需要替换 | 生成变量、填写说明、默认/示例值；删除客户实际值 |
| 场景专属资产 | 只服务某个完整场景，但可以跨客户复用 | 放入 `scenes/<scene-id>/` |
| 跨场景共享资产 | 被资产包内两个或更多场景明确引用 | 放入 `shared/`，由场景清单引用 |
| 客户覆盖 | 客户名称、组织、术语、字段映射、目录、输出格式等 | 不复制实际值；可生成空白覆盖模板 |
| 项目证据 | 访谈、确认、客户样例、过程记录、内部判断 | 只在来源追溯中做受控引用，不进入复用包 |
| 受限/权利未知 | 客户数据、凭证、专属策略、无许可第三方内容、权利不明源代码 | 排除；在审查文档记录原因 |

分类要点：

- "被两个或更多场景**明确引用**"才算跨场景共享；"可能以后共用"不是共享事实。
- 由客户需求/蓝图抽象出的通用场景定义、通用蓝图等抽象产物，默认归入**场景专属资产**；只有被两个及以上场景明确共用时才进入 `shared/`。
- 项目证据可以支撑"为什么这样设计"的追溯，但证据本身（访谈、截图、客户实际输出）不复制进资产包。
- 受限内容不是"删掉客户名称后放行"，而是排除并在 `客户隔离检查.md` 记录原因。

## 2. 资产包目录结构

```text
<资产暂存根目录>/
└── <asset-package-id>/
    ├── 资产包总览.md
    ├── 资产包清单.md
    ├── shared/                              # 仅保存两个及以上场景明确共用的内容
    │   ├── workbuddy/
    │   │   ├── skills/
    │   │   ├── experts/
    │   │   ├── prompts/
    │   │   └── prompt-templates/
    │   ├── source-code/
    │   ├── integration/
    │   │   ├── mcp-configuration-guide.md
    │   │   └── configuration-templates/
    │   └── enablement/
    │       └── shared-usage-guide.md
    ├── scenes/
    │   └── <scene-id>/
    │       ├── 资产清单.md
    │       ├── 场景定义.md
    │       ├── 场景蓝图.md
    │       ├── workbuddy/
    │       │   ├── skills/
    │       │   ├── experts/
    │       │   ├── prompts/
    │       │   └── prompt-templates/
    │       ├── source-code/
    │       ├── integration/
    │       │   ├── mcp-configuration-guide.md
    │       │   └── configuration-templates/
    │       ├── enablement/
    │       │   ├── 场景复用指南.md
    │       │   ├── 客户覆盖模板.md
    │       │   └── 培训材料模板.md
    │       └── examples/
    │           ├── 合成输入示例.md
    │           └── 合成输出示例.md
    └── governance/
        ├── 来源与转换追溯.md
        ├── 客户隔离检查.md
        ├── 权利与复用边界.md
        └── 资产包评审记录.md
```

目录规则：

1. 单场景包可以省略 `shared/`，但仍保留项目级总览和治理文件；
2. 共享文件只保存一份，场景 `资产清单.md` 通过相对路径引用；
3. 原始源代码和配置模板保留原生扩展名，Markdown 负责索引和解释；
4. 不创建空目录凑结构；没有专家、代码或 MCP 说明时不生成对应空文件夹；
5. 客户覆盖模板只能包含变量、说明和合成示例，不包含真实客户值；
6. 资产暂存根目录不得默认放在客户移交目录中，也不位于客户项目内部；
7. 不默认压缩为 ZIP，不自动上传或覆盖正式资产库。

## 3. `资产包总览.md` 内容合同

| 章节 | 必须包含 | 作用 |
|---|---|---|
| §1 资产包身份 | Package ID、名称、版本、Owner、来源项目受控引用、编制日期/状态 | 防止资产包被误认为已发布正式资产 |
| §2 业务定位 | 服务哪些岗位、解决什么通用任务、典型起点终点、业务价值方向 | 让后续 FDE 不看原项目也能判断适用性 |
| §3 场景组成 | Scene ID、名称、独立结果、依赖的共享资产、推荐组合 | 项目级快速导航 |
| §4 包含内容 | WorkBuddy Skills、专家、Prompt、模板、代码、MCP 说明、培训和示例摘要 | 知道包里实际有什么 |
| §5 适用与不适用 | 什么客户/任务可以使用，哪些情况必须重新设计或升级 | 防止被错误套用 |
| §6 复用方式 | 选择场景、复制/引用资产、填写客户覆盖、修改内容、形成客户交付材料的顺序 | 二次交付的操作路径 |
| §7 状态与限制 | 文档状态、复用状态、权利限制、未完成项、是否已提交评审 | 复用决策依据 |
| §8 本轮更新 | 本轮来源、更新内容和与既有资产的差异 | 支持连续修订和追溯 |

空白模板见 [../assets/templates/资产包总览.md](../assets/templates/资产包总览.md)。

## 4. `资产包清单.md` 与每场景 `资产清单.md` 内容合同

项目清单负责列出所有文件和场景映射；场景清单负责说明单个场景独立需要什么。两者共用以下字段：

| 字段 | 含义 |
|---|---|
| Asset ID | 稳定资产标识；已有标识沿用，新标识由 Skill 按规则建议 |
| 名称/类型 | Skill、专家、Prompt、模板、代码、MCP 说明、培训、示例等 |
| 所属 | `shared` 或具体 Scene ID |
| 资产包路径 | 在新资产包中的相对路径 |
| 来源项目路径 | 受控来源引用，不暴露到对外资产说明 |
| 处理方式 | 原样复制 / 参数化 / 合成重制 / 仅引用 / 排除 |
| 内容版本 | 文件或内容的版本标识；没有则标待补，不自动生成虚假正式版本 |
| 依赖 | 依赖的 Skill、Prompt、知识、代码或说明 |
| 客户差异 | 已删除、参数化或仍待处理的客户内容 |
| 权利状态 | 已确认范围 / 待确认 / 禁止复用 |
| 当前状态 | 草稿 / 待评审 / 已确认范围 |

每场景清单还必须说明：这个资产如何产生完整场景结果、最小输入、主要输出、人工确认点、可替换内容和共享资产引用。

空白模板见 [../assets/templates/资产包清单.md](../assets/templates/资产包清单.md) 和 [../assets/templates/场景资产清单.md](../assets/templates/场景资产清单.md)。

## 5. F1–F7 详细方法

### F1｜确定资产化范围和输出位置

- 识别项目路径、本轮 Scene ID、输出根目录、已有资产检索结果和本轮目标（新建/更新候选/仅分析）。
- 默认逐场景资产化；只有 FDE 明确要求时才生成多场景项目集合。
- 输出根目录检查：未提供 → 进入"仅候选分析"模式；指向客户项目或客户交付包内部 → 停止复制，要求独立暂存路径。
- 高影响补问示例："项目包含三个场景，其中'客户资料摘要'被两个场景共用。本轮是只归档销售拜访场景，还是生成包含两个场景和共享摘要 Skill 的项目资产包？"

### F2｜盘点项目并建立来源映射

- 读取顺序：已有资产包目标文件 → 本轮直接提供的源文件 → 场景需求与蓝图 → 阶段 4/5 文档 → 与本轮场景明确关联的实际 WorkBuddy 内容。
- 不默认遍历全部项目历史、归档和客户原始证据；FDE 给目录时先按本轮场景、文件名和目录位置筛选，并告知实际读取范围。
- 输出"项目文件 → 场景 → 内容类型 → 计划处理方式"映射，形成初版 `资产包清单.md` 和 `来源与转换追溯.md`（仅分析模式时留在对话）。

### F3｜分类可复用核心、客户覆盖和排除项

- 对每个候选文件执行第 1 节分类。
- 特别检查：
  - 客户专属 Prompt 是否能安全参数化（变量替换后核心边界是否仍成立）；
  - 客户字段映射是否应转成空白覆盖模板；
  - 源代码是否含客户常量、地址或第三方内容；
  - MCP 配置是否含客户地址、账号、凭证或真实 Schema；
  - 项目证据（访谈、截图、客户实际输出）是否被误当为资产示例。
- 冲突或权利不清时不复制，先提出高影响问题；权利未知项默认"待确认"，不是默认放行。

### F4｜生成场景资产骨架和共享结构

- 根据实际内容创建需要的目录，不创建空目录。
- 为每个场景生成 `资产清单.md`、`场景定义.md`、`场景蓝图.md` 和复用指南骨架。
- 场景定义和蓝图从客户版本抽象为通用版本：保留任务、流程、边界和人工确认点，移除客户专属结论（客户术语、专属输出格式、客户组织名称）；无法通用化的部分放入 `客户覆盖模板.md` 或排除。
- 被多个场景明确共用的内容放入 `shared/`，场景文件通过相对路径引用同一版本。

### F5｜归档 WorkBuddy 内容和原生文件

- 在权利和客户隔离允许的范围内，将实际 Skill、专家、Prompt、模板、代码和 MCP 说明复制/重制到对应目录；为原生文件生成 Markdown 索引和说明。
- 各类资产的保留结构、必须附带说明和检查项见 [workbuddy-asset-types.md](workbuddy-asset-types.md)。
- 关键规则：不修改客户项目原文件；不覆盖已有正式资产；同名冲突时生成更新候选或请 FDE 选择，不静默替换；无法读取或无法确认权利的文件只登记不复制；复制后仍需执行内容级客户隔离检查，不能只检查文件名。

### F6｜生成二次交付和客户覆盖指南

为未来 FDE 说明六件事：

1. 如何选择场景和共享资产；
2. 复制或引用哪些 WorkBuddy 内容；
3. 如何填写客户术语、角色、目录、输出格式、Prompt 变量和 MCP 配置占位；
4. 哪些内容需要重新开展客户需求确认；
5. 怎样利用 `fde-deliver` 生成新客户交付材料；
6. 哪些变化属于资产核心调整，必须提交专业 FDE/资产 Owner。

输出每场景 `场景复用指南.md`、`客户覆盖模板.md` 和可选培训材料模板。

### F7｜完成隔离、复用和评审准备

- 检查文件路径、场景映射、共享引用、来源追溯、客户信息、权利和复用说明。
- 填写 `governance/` 四份治理文档（填写方法见 [de-identification-rules.md](de-identification-rules.md)）。
- 最终状态定级：

| 结果 | 条件 | 可以怎样使用 |
|---|---|---|
| 草稿候选 | 结构或来源仍不完整 | 仅继续内部编制 |
| 待评审资产包 | 场景闭环、文件和追溯完整；客户隔离完成；权利/质量等待专业确认 | 可提交资产 Owner，不可对外复用 |
| 已确认范围资产包 | 有明确专业评审/Owner 确认及适用范围 | 可按确认范围用于后续项目准备，仍不等于已公开发布 |
| 禁止复用 | 存在无法隔离的客户内容、权利限制或严重缺失 | 只保留受控项目记录，不进入资产包 |

Skill 不自我批准："已确认范围"必须有明确专业评审或 Owner 确认来源。

## 6. 完整示例：销售拜访准备助手资产化

以下为合成教学示例（设计文档 6.4 节），展示客户项目内容怎样转成资产包结果。

客户项目情况：场景 `SCN-SALES-VISIT-PREP`（销售拜访准备），包含客户版 `sales-visit-prep` Skill、两个专家、简报生成 Prompt、五段式简报模板、可选脚本、客户版 MCP 配置说明；客户差异为"客户经理"称谓、专属五段式输出、客户资料目录和字段名称。

| 客户项目内容 | 归档处理 | 资产包结果 |
|---|---|---|
| 客户版 `sales-visit-prep` Skill | 去除客户名称和专属模板引用，保留通用流程与人工边界 | `scenes/SCN-SALES-VISIT-PREP/workbuddy/skills/sales-visit-prep/` |
| "客户经理"称谓 | 参数化为 `${sales_role_name}` | `enablement/客户覆盖模板.md` |
| 客户五段式标题 | 替换为通用章节变量和合成默认示例 | `workbuddy/prompt-templates/visit-brief-template.md` |
| 客户资料字段 | 不复制真实字段，改成业务语义变量 | `integration/mcp-configuration-guide.md` |
| 客户域名、账号和凭证 | 完全排除 | `governance/客户隔离检查.md` 记录排除 |
| 客户访谈和实际简报 | 不进入资产；用虚构公司和客户重制 | `examples/合成输入示例.md`、`合成输出示例.md` |
| 两个场景共用的产品知识专家 | 若被多个场景明确引用，移到 shared | `shared/workbuddy/experts/product-knowledge-expert/` |

生成后的场景资产必须能回答六个问题：

1. 这个场景解决什么完整业务任务；
2. 需要哪些 WorkBuddy 内容；
3. 哪些变量每个客户都要重新填写；
4. 哪些核心边界不能因客户适配而删除；
5. 怎样利用 `fde-deliver` 生成新客户的交付说明和培训材料；
6. 哪些变化必须重新进入需求或蓝图设计。
