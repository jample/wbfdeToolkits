# 各类 WorkBuddy 资产的归档要求

> 本文件规定五类 WorkBuddy 资产进入资产包时的保留结构、必须附带的说明和归档检查项。通用规则：本 Skill 只组织和说明资产，不运行 Skill、不执行源代码、不验证 MCP 连接；发现缺失引用、名称不一致或客户内容残留时写入评审记录，并在得到 FDE 明确选择后修订候选包。

## 1. WorkBuddy Skill

**保留的文件结构：**

- `SKILL.md`：name、description、核心工作流和引用；
- `references/`：方法、字段、业务规则和适配说明；
- `assets/`：模板、示例输入、可复制文件；
- `scripts/`：若实际存在且允许复用，保留源代码和依赖说明；
- `agents/openai.yaml`：若实际存在，保留与 Skill 当前用途一致的界面元数据。

**必须附带的说明：**

- Skill 与 Prompt、专家、代码、MCP 说明的依赖关系；
- 哪些内容是通用核心，哪些由客户覆盖模板提供。

**归档检查项：**

- `SKILL.md` 的 name、description、核心工作流和引用是否完整；
- 内部相对链接是否仍指向包内真实文件；
- 是否残留客户名称、客户目录、客户专属模板引用；
- scripts 的复用权利和依赖说明是否具备。

## 2. 专家与专家团

**保留的文件结构：** 专家定义文件（Markdown 或原生格式），专家团保留各成员定义和协作说明。

**必须附带的说明：**

- 专家角色、擅长任务、输入、输出、选择/协作方式；
- 禁止替代的人类判断；
- 依赖的 Skill、知识和 Prompt；
- 适用和不适用场景。

**归档检查项：**

- 客户组织名称和具体人员不能成为通用专家身份；
- 专家职责描述中不含客户专属业务规则；
- 与场景步骤的对应关系清楚。

## 3. Prompt 与 Prompt 模板

**保留的文件结构：** 优先使用 Markdown；Prompt 模板保留变量占位。

**必须附带的说明：**

- 用途和关联场景步骤；
- 输入变量、类型/含义、必需/可选和缺失处理；
- 输出结构和用户核对点；
- 事实依据、禁止编造和安全边界；
- 可由客户覆盖的变量与不应修改的核心约束；
- 一条合成输入和输出示例；
- 内容版本和 Owner。

**归档检查项：**

- 客户真实 Prompt 中的名称、目录、策略、人员、价格、账号或专属字段已参数化或重制，**不能只全文搜索替换**；
- 核心约束（事实边界、人工确认点）未被当作可覆盖变量；
- 合成示例不含任何客户真实值。

## 4. 源代码

**保留的文件结构：** 保留原目录结构和原生扩展名（Python、JavaScript、配置等）；同时生成 `source-code/源代码说明.md`。

**`源代码说明.md` 至少包含：**

- 代码组件及用途；
- 与哪个场景步骤、Skill 或 Prompt 关联；
- 入口文件和主要目录；
- 依赖及准备方式；
- 必需配置项和敏感配置的引用方式；
- 客户专属代码/常量是否已经移除或参数化；
- 已知限制和维护 Owner；
- 复用权利或第三方许可状态。

**归档检查项：**

- 权利未知的代码不复制到资产包，只在受控追溯中登记；
- 代码中不含客户常量、内网地址、账号或凭证；
- 第三方依赖的许可状态有记录；
- 本 Skill 不执行构建或环境验证，说明中不声称"已验证可运行"。

## 5. MCP 配置说明和模板

**保留的文件结构：** `integration/mcp-configuration-guide.md`（Markdown）+ `configuration-templates/`（脱敏后的 YAML/JSON 等原生格式模板）。

**`mcp-configuration-guide.md` 至少包含：**

| 章节 | 内容 |
|---|---|
| 业务用途 | 该 MCP 能力服务哪个场景步骤，WorkBuddy 需要取得或提交什么信息 |
| 工具清单 | 工具名称、意图、主要输入、主要输出和人工边界 |
| 数据含义 | 业务对象和字段语义，不复制客户真实 Schema |
| 配置变量 | 服务地址占位、认证方式说明、凭证引用、超时/范围等可配置项 |
| 映射说明 | 输入到工具、工具结果到场景输出的语义对应和可调整点 |
| 客户覆盖 | 客户需要填写什么，哪些内容禁止放入通用模板 |
| 使用限制 | 只读/可编辑的说明、权限要求、错误处理和不适用情形 |
| 合成示例 | 不含客户地址、Token、账号、字段或真实数据的配置片段 |

空白模板见 [../assets/templates/mcp-configuration-guide.md](../assets/templates/mcp-configuration-guide.md)。

**归档的配置模板（YAML/JSON）必须：**

- 使用占位变量而不含明文凭证；
- 移除客户域名、租户、内网地址、账号和专属字段；
- 在 Markdown 中解释每个变量，而不是留下不可读的裸配置；
- 权限或用途不清时保持待评审，不声称可直接使用。

**归档检查项：**

- 配置说明与场景步骤的对应关系明确；
- 凭证只写引用方式，不出现任何真实值；
- 客户真实 Schema 未进入模板，字段用语义变量表达。
