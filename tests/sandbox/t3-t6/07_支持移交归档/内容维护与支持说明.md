## 1. 内容维护责任

| 内容域 | 客户可维护内容 | 建议维护方式 | 需要 FDE/专业支持的情况 |
|---|---|---|---|
| 客户术语和角色称谓 | "销售代表/经理/对应负责人"的显示称谓（客户实际称谓待提供） | 内容维护人修改客户覆盖内容并记录日期/修改人；称谓变化不改变角色判断权 | 称谓调整涉及责任边界或多个场景时 |
| Prompt 变量 | 回复模板 {客户称谓}/{公司签名}/{格式偏好}；首次行动记录字段称谓 | 内容维护人按模板说明修改并记录版本与摘要；不改事实边界与人工确认点 | 需要改变任务逻辑或人工确认点时 |
| Prompt 模板 | 回复草稿模板中已开放变量对应段落 | 保留模板版本与变更摘要 | 删除事实来源引用段落/人工发送提示，或出现跨场景影响时 |
| 业务知识/规则 | 查重与疑似处理口径（待业务 Owner 确认后登记） | 标来源、Owner、适用范围和更新时间 | 权威口径冲突、疑似终态确认责任不清时 |
| WorkBuddy Skill/专家 | inquiry-intake 的客户覆盖配置（称谓、模板引用、目录变量） | 内容维护人按交付权利和维护指南修改 | 修改 Skill 核心指令（只展示不下结论、草稿不发送、写回人工确认）时 |
| 源代码 | 本项目无源代码交付 | 不适用 | 不适用 |
| MCP 配置说明 | 非敏感参数（后台地址、目录字段名）和凭证引用位置 | 客户技术联系人填写；不在文档存明文凭证，保留客户自己的配置记录 | 需要新的工具、复杂映射或实际连接处理时 |
| 新场景 | 不直接塞入既有场景 | 重新从需求探究开始 | 由项目 FDE 重新评估范围 |

## 2. 问题路由

| 问题类型 | 接收方 | 提交所需最小信息 |
|---|---|---|
| 使用疑问 | 先查场景交付说明/培训指南，再找用户代表（销售主管） | 场景 ID、操作步骤、实际输出 |
| 内容错误 | 内容维护人（待指定）；涉及业务规则时升级业务 Owner（销售运营负责人） | 错误输出、对应来源材料（EvidenceRef）、期望结果 |
| 客户适配调整 | 内容维护人（待指定，允许范围内） | 变更内容、影响场景、Owner 确认 |
| Skill/代码修改 | 项目 FDE | 变更目的、影响范围、是否涉及核心边界 |
| 新场景需求 | 项目 FDE，重新从需求探究开始 | 业务任务、触发、期望结果 |

## 3. 问题提交最小信息

- 场景 ID：如 SCN-INQUIRY-INTAKE
- 操作步骤：从发起到出问题环节的操作序列
- 输入材料：当时的消息清单/记录（脱敏后）
- 实际输出：含 EvidenceRef 的实际输出
- 期望输出：期望的正确结果
