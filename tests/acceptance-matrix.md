## 5. 单 Skill 完成标准（设计 15.9 节）

### 5.1 开发启动条件

- 采用设计第 15.3 节的主要输出，不再增加首期强制业务文档。
- 将第 11–13 节分别转写为三个 `SKILL.md` 的执行流程。
- 将第 15.4–15.6 节作为三个 Skill 共用的合并、补问和质量规则。
- 以第 15.8 节测试矩阵（即本文件第 2 节）建立固定输入夹具和期望输出断言（夹具见 `fixtures/`）。

### 5.2 单个 Skill 的首期实现完成标准

全部满足才可标为完成：

- 最小输入测试、资料不全测试、增量修订测试通过（即 P1、X1/X2、C3 类测试）。
- 至少一个跨境电商端到端测试通过（本文件第 3 节序列中覆盖该 Skill 的步骤）。
- 目标输出能独立阅读（不依赖对话上下文才能看懂）。
- FDE 不填写额外内部文件（内部 `RunRequest`、去重、状态均由 Skill 维护）。
- 在无确认、无系统资料或来源冲突时不会生成过度确定的结论（X4、B1/B3、C2 类测试覆盖）。
- 第 4 节资产完整性检查中该 Skill 相关项全部通过。

### 5.3 首期明确暂不包含范围

以下能力**不得**成为 v0.6 三个核心 Skill 上线的前置条件：

- 06/07 阶段 Skill 的实现（注：后续阶段已由 v0.7 设计的 `fde-deliver`、`fde-transfer`、`fde-assets-archive` 承接，验收见本文件第 6–7 节）；
- 生产 API 权限验证；
- 运行时字段映射 DSL；
- 多客户并行项目管理；
- 自动化 ROI 计算。

## 7. v0.7 单 Skill 完成标准（v0.7 设计第 9.2–9.4 节）

### 7.1 fde-deliver

- 能从需求、蓝图和自然语言识别本轮场景；
- 能盘点真实 WorkBuddy 内容并形成场景映射；
- 能生成三份可直接供 FDE 修改和客户阅读的 Markdown；
- 能生成角色化培训和业务任务练习；
- 能区分通用核心、客户适配、待补和客户确认；
- 不操作外部系统，不虚构实际文件。

### 7.2 fde-transfer

- 能读取阶段 4 交付内容和实际文件目录；
- 能按场景、内容类型、交付方式和权利形成客户目录；
- 能生成客户维护责任和问题路由；
- 能记录完整接收、条件接收、暂缓和未形成；
- 不把内部资料和资产候选默认交给客户；
- 没有实际确认时不写已接收。

### 7.3 fde-assets-archive

- 能以场景为最小单元、项目为聚合单元建立资产包；
- 能归档 WorkBuddy Skill、专家、Prompt、模板、代码和 MCP 配置说明；
- 能保留原生文件结构并生成 Markdown 索引和复用说明；
- 能分类通用核心、参数化模板、客户覆盖、项目证据和受限内容；
- 能生成来源追溯、客户隔离、权利边界和评审记录；
- 能处理共享资产和已有正式资产更新候选；
- 不写回客户项目、不覆盖正式资产、不自动发布。

## 8. fde-init（项目初始化）验收矩阵（v0.8 新增）
